# Flutter controller implementation rules

Read the parent AGENTS.md and ../docs/CONTEXTUAL-UI.md in full before changing this app. The current basic design is explicitly rejected, and all unified-controller acceptance rules in the parent apply to this directory.

- One integrated, activity-oriented PCController/Pealayer workspace; no separate product tabs. Offer compact expert controls, responsive phone/tablet composition, meaningful headers/cards/dialogs, coherent semantic colors, icons, charts and pills.
- A peer has one connection action reflecting its actual lifecycle. The latest direct request uses one compact lifecycle toggle: Connect, Cancel while connecting, or Disconnect when connected. Never show competing connection verbs together. Keep explicit disconnect discovery opt-out and Connect/Cancel lifecycle handling. Omit unavailable-only cards, irrelevant actions, dormant access-token fields and filler narration. Unknown is not zero. Keep useful warnings, safety restrictions and failed/uncertain operation receipts.
- Appearance/branding preferences must update the actual Android activity/task presentation and selectable launcher aliases. Preserve one or both launcher entries for the same unified app and include PakarController palettes without replacing existing schemes.
- Discovery is DNS-SD/mDNS, SSDP and MNDP with verified product/endpoint metadata. Automatic connection respects saved intent and the live selected peer; it must not seize board authority, actuate hardware or replay an uncertain command.
- Peer APK transfers/upgrades share IPC/RPC and must be bounded, integrity-checked, package/signature-checked and mediated by Android installation consent. Do not remove existing protected local automation security to hide an irrelevant remote-peer token UI.
- Preserve dirty work and active owner file scopes. Do not claim design or physical acceptance from compilation, fixture rendering or APK delivery. Keep screenshots honest and separate controlled fixtures from actual device/network state.
- MOSFET/PWM edits retain their drag and pending setpoint until the guarded command and fresh authoritative readback finish. Fence pre-write reads and changed owners; never replace a pending edit with an older observation, invent zero, claim optimistic applied state or retry uncertain actuation.
- PWM has a readback freshness budget consistent with its polling cadence, independent of fast status telemetry. Retain same-owner last good readbacks through expiry/unavailable/incomplete reads, marking them Stale and disabling edit while preserving slider/card geometry. Only a changed board/host/connection clears ownership-bound values; unknown with no observation is never zero. Automation exposes current PWM only when its own readback is fresh.
- Preferences persist relay-card layout: compact one-line controls by default, or two-line cards with explicit ON/OFF actions. Both use the same observed state, channel ownership, lock and safety guards.
- Relay ON/OFF actions use green/red semantic colors, not the branding/accent seed, across filled/tonal/outlined styles and compact/menu controls. Disabled actions remain muted. Card captions, action labels, fact rows and state pills share centered text leading; desktop inline captions/editors must keep matching font/inset/slots.
- Uncompact Live restores full connection cards with an actual Connected/Host only/Connecting/Offline pill, including the first PCController card. Each available telemetry series gets its own full-width chart row, including separate lighting and audio temperature charts; compact mode retains its metric grid.
- Global request progress reserves its layout space in idle and busy states. Front-panel actions and other loading transitions must not move the scroll viewport, change its extent or reset its position.
- Pull-to-refresh works at the top of every main activity, including short content. Its indicator overlays a full-height scroll viewport; it never inserts rows or clears authoring drafts. Refresh joins current-owner in-flight reads, discards replaced-owner results, and only reads selected peer state/catalog/PWM plus contextual firmware status/catalog. Network/offline refresh may scan nearby peers without automatic connection or changed saved connection intent. Failures remain actionable without resizing the page; no actuation, mutation replay or firmware preparation/download/upload is part of refresh.
- Outputs support handle-only drag/drop reorder and inline caption rename using the native revision-checked presentation RPC, not device-only ordering. Preserve hidden ranks, output-kind and raw-wiring constraints, identity-keyed card/editor state and authoritative receipts. Cancel/unchanged edits send nothing; stale owners or revisions cannot receive an edit, and older catalog reads cannot overwrite acknowledged presentation. Inline edit shares the caption font, inset and fixed height.
- Retain previous neutral surfaces, muted accent palette and classic card headers as the Pastel (muted) appearance option; retain the current appearance as Vibrant. Persist independent header and actual action-button styles. Appearance changes must preserve indicators, accessibility targets, disabled safety state and command ownership without any hardware action.
- Buzzer mirroring preserves fresh short-note durations and device cadence with bounded startup buffering and ahead-of-time native audio-frame scheduling. Follow the Linux 50ms playout/250ms freshness policy; stale observations and changed owners never replay. Ordinary transitions/endings never pause/flush queued PCM; explicit Stop and lifecycle/focus/lease cutoffs do. Retain partial AudioTrack writes, use a band-limited passive-buzzer-style waveform with short edge ramps, and handle temporary focus ducking without dropping the session. PCM/source tests and installed APK identity do not prove audible fidelity on an Android speaker.

- Preserve the phased PU850 imports in PU850-IMPORT-LEDGER.md. Connection input normalizes localized digits/separators, admits explicit modern HTTP(S)/WS(S)/IPv6 endpoints and validates ports, credentials and known service paths inline. Read-only detection verifies the requested product on bounded same-host candidates, never forwards credentials or follows redirects, and preserves explicit port/TLS intent. Edits/cancel retire probes; saved offline intent is explicit. Native network recovery only wakes the selected enabled peer, coalesces opens, preserves request/response-only relay routing and never replays commands. Shared dialogs retain explicit Close/Cancel, keyboard-safe scrolling, accessible targets and stable progress/error slots. Keep the imported font license/notice and separate fixture rendering from live Android acceptance.

- The latest contextual-utility rejection remains authoritative: no idle effect Cancel/Stop actions, empty live-only cards, unavailable-only fact cards or static "last values unavailable" narration. Keep actionable exceptions and useful offline editors. Hardware controls use balanced equal-width action rows within compact cards, semantic ON/OFF colors and directly clickable observed relay indicators with the same current-owner/lock/E-STOP gates. Folder assignment is a catalog-driven dropdown scoped to output kind and preserving raw folder identity, not a plain text field. Refresh is explicit and event-driven; only failed/stale/unsupported WebSocket transport uses bounded fallback reads. Preserve acknowledged PWM drafts, current profile-resolved names, and owner/revision fences. Native network discovery, auto-connect intent, branding/task icons and dual launcher aliases, all existing color schemes and integrity-checked peer IPC/RPC app transfers remain acceptance requirements. Defer remote multi-step authentication until supported; hide unused remote token fields without weakening protected local automation. Every new surface follows this contract without another user reminder.
